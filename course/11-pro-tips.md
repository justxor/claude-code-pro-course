# Модуль 11. Продвинутые приёмы и чек-лист профи

## 1. Параллельная работа: git worktrees

Несколько Claude одновременно над разными задачами без конфликтов:

```bash
git worktree add ../proj-feature-a -b feature-a
git worktree add ../proj-bugfix-b  -b bugfix-b
cd ../proj-feature-a && claude     # терминал 1
cd ../proj-bugfix-b  && claude     # терминал 2
```

Во многих версиях есть встроенная поддержка: `claude --worktree` / `-w` создаёт изолированный worktree автоматически. Уберите за собой: `git worktree remove ../proj-feature-a`.

## 2. Мульти-агентные паттерны

- **Писатель / ревьюер:** Claude A пишет, Claude B (чистый контекст) ревьюит, Claude A исправляет по замечаниям.
- **Тестировщик / разработчик:** один пишет тесты, другой — код, чтобы тесты прошли.
- **Фоновые задачи:** долгие команды (dev-сервер, сборка) можно запускать в фоне — Claude продолжает работу и читает их вывод.

## 3. Экономия токенов и денег

| Приём | Эффект |
|---|---|
| `/clear` между задачами | Главная экономия |
| Короткий CLAUDE.md, правила в `.claude/rules/` с `paths` | Меньше постоянного контекста |
| Skills вместо «простыней» в CLAUDE.md | Грузятся по требованию |
| Subagents на Haiku для поиска | Дешёвое исследование |
| Отключить неиспользуемые MCP | Меньше описаний инструментов |
| Конкретные промпты с `@файлами` | Меньше блужданий по проекту |
| `/cost`, `/context`, statusline | Видеть расход в реальном времени |

## 4. Своя статусная строка

```
/statusline покажи модель, ветку git и процент заполнения контекста
```
Claude сам напишет скрипт и пропишет его в настройках.

## 5. Output styles

Меняют «манеру» Claude: например, режим обучения, где он объясняет решения и оставляет вам куски для самостоятельной реализации.
```
/output-style            # выбрать стиль
```
Свои стили — markdown-файлы в `~/.claude/output-styles/` или `.claude/output-styles/`.

## 6. Безопасность — чек-лист

- [ ] `.env`, ключи, `secrets/` — в `deny` на чтение.
- [ ] Опасные команды (`rm -rf`, `git push --force`, `curl | sh`) — в `deny` или под hook.
- [ ] `bypassPermissions` — только в контейнере/devcontainer без доступа к секретам.
- [ ] MCP-серверы только из доверенных источников, БД — read-only.
- [ ] Hooks и skills из чужих репозиториев — прочитать перед использованием.
- [ ] Контент из интернета/issues считается недоверенным (prompt injection).
- [ ] Ревью диффов в критичных местах: auth, платежи, миграции, инфраструктура.

## 7. Командная настройка — чек-лист

- [ ] `CLAUDE.md` в git, ревью через PR.
- [ ] `.claude/settings.json` с общим allowlist и deny.
- [ ] `.claude/settings.local.json` и `CLAUDE.local.md` в `.gitignore`.
- [ ] Общие skills в `.claude/skills/`, агенты в `.claude/agents/`.
- [ ] `.mcp.json` без секретов, через `${VAR}`.
- [ ] Hooks для форматирования и защиты файлов.
- [ ] GitHub Action для `@claude` и авто-ревью.
- [ ] Для нескольких репозиториев — свой плагин и маркетплейс.

## 8. Типичные ошибки и их решения

| Проблема | Решение |
|---|---|
| Claude игнорирует правило из CLAUDE.md | Файл слишком длинный → сократить; добавить акцент; сделать hook |
| «Исправил», но не работает | Требовать запуск тестов/проверки в промпте |
| Уходит в сторону, трогает лишние файлы | Plan mode + явные границы «меняй только X» |
| Качество падает к концу сессии | `/compact` или `/clear` + файл с планом |
| Слишком много вопросов о разрешениях | Allowlist в settings, `acceptEdits` |
| Галлюцинирует API библиотеки | Context7 MCP / ссылка на доки / `@node_modules/.../*.d.ts` |

## 9. Итоговый чек-лист профи

- [ ] Использую Plan mode для задач сложнее одного файла
- [ ] Всегда даю Claude способ проверить результат
- [ ] `/clear` между задачами — привычка
- [ ] CLAUDE.md < 200 строк и регулярно обновляется
- [ ] 3+ собственных skill для повторяющихся процессов
- [ ] 2+ субагента (ревьюер, дебаггер)
- [ ] Hook автоформата и защиты файлов
- [ ] Хотя бы один полезный MCP (GitHub / браузер / БД)
- [ ] `claude -p` в скриптах или CI
- [ ] Параллельные сессии через worktrees
