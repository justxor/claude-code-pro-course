# Модуль 06. Subagents

**Subagent** — отдельный экземпляр Claude со своим системным промптом, набором инструментов и, главное, **собственным контекстом**. Основной агент делегирует ему задачу и получает только итог.

## Зачем

1. **Экономия контекста.** Поиск по 200 файлам происходит в контексте субагента, вам возвращается короткий вывод.
2. **Специализация.** Ревьюер с чек-листом, дебаггер с методикой, тест-раннер.
3. **Ограничение прав.** Ревьюеру не нужен `Edit` — не давайте.
4. **Параллельность.** Несколько субагентов исследуют разные части кода одновременно.

## Встроенные

Claude уже использует встроенные субагенты (например, `Explore` для поиска по коду, `Plan` для планирования) — часто сам. Можно просить явно:
```
> используй субагентов, чтобы параллельно изучить модули auth, billing и notifications
```

## Свои субагенты

| Путь | Область |
|---|---|
| `.claude/agents/<name>.md` | Проект |
| `~/.claude/agents/<name>.md` | Лично вам |

Создать интерактивно: `/agents`.

```markdown
---
name: code-reviewer
description: Опытный ревьюер. Используй ПРОАКТИВНО сразу после написания или изменения кода.
tools: Read, Grep, Glob, Bash
model: sonnet
---

Ты senior-ревьюер. При вызове:
1. Выполни `git diff`, сфокусируйся на изменённых файлах.
2. Проверь: читаемость, дублирование, обработку ошибок, секреты, валидацию ввода, тесты, производительность.
3. Выдай отчёт по приоритетам: критично / предупреждения / предложения — с конкретными исправлениями.
```

### Поля

| Поле | Зачем |
|---|---|
| `name` | Идентификатор |
| `description` | Когда делегировать. «PROACTIVELY / ПРОАКТИВНО» повышает шанс авто-вызова |
| `tools` | Список разрешённых инструментов (нет поля → наследует все) |
| `model` | `sonnet`, `opus`, `haiku`, `inherit` или полный ID |

## Вызов

```
> попроси code-reviewer проверить мои изменения
> @code-reviewer посмотри последний коммит
```

Или Claude вызовет сам, если описание подходит.

## Паттерны

### Писатель + ревьюер
Один агент пишет, второй (с чистым контекстом) ревьюит. Свежий взгляд находит больше ошибок, чем «проверь сам себя».

### Исследователь → исполнитель
```
> используй субагента, чтобы найти все места, где вызывается legacy API, и вернуть список файл:строка.
> теперь мигрируй их по одному, с тестами
```

### Параллельный анализ
```
> запусти 3 субагента: безопасность, производительность, покрытие тестами. Сведи отчёты в один.
```

## Subagent vs Skill

| | Skill | Subagent |
|---|---|---|
| Контекст | Общий с основной сессией | Отдельный |
| Для чего | «Как делать» — процедура, знания | «Кто делает» — изолированный исполнитель |
| Видит историю разговора | Да | Нет — только задачу |
| Результат | В ходе основной сессии | Сводка обратно |

Их можно комбинировать: subagent может использовать skills.

## Практика

1. Скопируйте агентов из starter-kit, выполните `/agents` — убедитесь, что видны.
2. Напишите код и попросите `code-reviewer` его проверить.
3. Запустите параллельное исследование трёх модулей и сравните расход контекста (`/context`) с последовательным.
