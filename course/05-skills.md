# Модуль 05. Skills и slash-команды

**Skill** — папка с инструкцией `SKILL.md` (и, при желании, скриптами и шаблонами), которую Claude использует для конкретного типа задач. Вызывается вручную (`/имя`) или автоматически, когда задача подходит под описание.

> Раньше были отдельно «custom slash commands» (`.claude/commands/*.md`). Сейчас они объединены со skills: старые команды продолжают работать, но новый формат — skills.

## Где лежат skills

| Путь | Область |
|---|---|
| `.claude/skills/<name>/SKILL.md` | Проект (в git, для команды) |
| `~/.claude/skills/<name>/SKILL.md` | Лично вам, во всех проектах |
| `<plugin>/skills/<name>/SKILL.md` | Из плагина (`/plugin:name`) |
| `.claude/commands/<name>.md` | Старый формат команд — всё ещё работает |

## Анатомия SKILL.md

```markdown
---
name: code-review
description: Ревью изменений в текущей ветке. Используй, когда просят проверить код, сделать ревью или перед созданием PR.
allowed-tools: Bash(git diff:*), Bash(git log:*), Read, Grep, Glob
---

# Code review

1. Получи изменения: `git diff main...HEAD`
2. Для каждого файла проверь:
   - корректность и граничные случаи
   - безопасность (инъекции, секреты, права)
   - тесты для нового поведения
3. Выведи отчёт: 🔴 критично / 🟡 стоит исправить / 🟢 мелочи.
   Для каждого пункта: файл:строка, проблема, предложение.
```

### Поля frontmatter

| Поле | Зачем |
|---|---|
| `name` | Имя и команда вызова `/name` |
| `description` | **Самое важное.** По нему Claude решает, когда применить skill. Пишите: *что делает* + *когда использовать* |
| `allowed-tools` | Инструменты, разрешённые без вопросов во время работы skill |
| `disable-model-invocation: true` | Только ручной вызов (например, для деплоя) |
| `model` | Модель для этого skill |
| `argument-hint` | Подсказка аргументов в меню |

## Аргументы

```markdown
---
name: fix-issue
description: Исправить GitHub issue по номеру
argument-hint: <номер issue>
---
Исправь issue #$ARGUMENTS:
1. `gh issue view $ARGUMENTS`
2. Найди код, напиши падающий тест, исправь
3. Коммит `fix: ... (closes #$ARGUMENTS)`
```

Вызов: `/fix-issue 142`. Также доступны позиционные `$1`, `$2`.

## Динамический контекст

В командах можно подставить вывод shell-команды строкой с `!`:

```markdown
## Текущее состояние
- Ветка: !`git branch --show-current`
- Изменения: !`git status --short`
```

И файлы через `@path`.

## Skills со скриптами и ресурсами

```
.claude/skills/release-notes/
├── SKILL.md
├── template.md          # шаблон, на который ссылается SKILL.md
└── scripts/
    └── collect.sh       # Claude запускает скрипт, а не пишет логику заново
```

Прогрессивная загрузка: в контексте всегда лежит только `name` + `description`. Тело SKILL.md читается, когда skill нужен, а дополнительные файлы — только если SKILL.md на них сошлётся. Поэтому skills могут быть большими без вреда для контекста.

## Когда делать skill

- Вы в третий раз пишете один и тот же длинный промпт.
- Есть процесс с шагами: релиз, ревью, миграция, онбординг.
- Нужны знания, которые не должны лежать в CLAUDE.md постоянно (экономия контекста).

## Советы по description

❌ `description: помощь с тестами`
✅ `description: Пишет unit-тесты на Vitest для указанного файла или функции. Используй, когда просят добавить тесты, покрыть код или проверить граничные случаи.`

## Практика

1. Скопируйте `starter-kit/.claude/skills/` в проект, вызовите `/code-review`.
2. Создайте свой skill для самого частого повторяющегося промпта.
3. Проверьте авто-вызов: попросите задачу своими словами, не упоминая skill.
