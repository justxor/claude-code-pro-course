# Модуль 04. Workflow профи

## 1. Explore → Plan → Code → Commit

Самый надёжный базовый цикл.

```
1. EXPLORE   > прочитай src/billing/ и объясни, как считается скидка. Код пока не меняй.
2. PLAN      [Shift+Tab → plan mode] > составь план добавления промокодов
3. CODE      > реализуй план. После каждого шага запускай тесты.
4. COMMIT    > сделай коммит и открой PR с описанием
```

**Plan mode** (`Shift+Tab` дважды или `claude --permission-mode plan`) — Claude только читает и предлагает план. Вы правите план до того, как написана хоть строка кода. Это дешевле любого рефакторинга.

Совет: попросите сохранить план в файл (`docs/plans/promo.md`) — к нему можно вернуться после `/clear`.

## 2. TDD с Claude

Claude отлично работает, когда есть **чёткая цель, которую можно проверить**.

```
> Напиши тесты для функции parseDuration по этим примерам: "1h30m" → 5400, "90s" → 90,
  "abc" → ошибка. Это TDD — реализацию НЕ пиши. Запусти тесты, убедись, что падают.
> Закоммить тесты.
> Теперь напиши реализацию, чтобы тесты прошли. Тесты не меняй.
```

## 3. Визуальная итерация

Для UI: макет → код → скриншот → сравнение → исправление. С MCP для браузера (Playwright/Chrome) Claude сам делает скриншоты. 2–3 итерации дают результат намного лучше первого.

## 4. Дайте способ проверки

Самый сильный рычаг качества. Вместо «сделай» — «сделай и проверь»:

- тесты (`npm test`),
- типы (`tsc --noEmit`),
- линтер,
- запуск скрипта и сравнение вывода,
- скриншот UI.

## 5. Управление контекстом

Контекстное окно — ограниченный ресурс. Чем оно полнее, тем хуже Claude следует инструкциям.

| Инструмент | Когда |
|---|---|
| `/clear` | Новая задача. Используйте часто! |
| `/compact [фокус]` | Длинная задача, нужно продолжить. `/compact сохрани решения по API` |
| `/context` | Посмотреть, что съедает контекст |
| Subagents | Поиск/исследование в отдельном контексте (модуль 06) |
| Файл-заметки | `PLAN.md`, `NOTES.md` — «внешняя память» между сессиями |

## 6. Чекпоинты и откат

- Claude автоматически сохраняет состояние файлов перед правками.
- `Esc Esc` или `/rewind` — откатить разговор и/или код к выбранной точке.
- Чекпоинты не заменяют git: коммитьте рабочие состояния.

## 7. Сессии

```bash
claude -c              # продолжить последнюю сессию
claude -r              # выбрать сессию из списка
/resume                # то же внутри
/rename auth-refactor  # дать сессии имя (если доступно)
```

## 8. Работа с git

Claude умеет всё: история, конфликты, коммиты, PR (через `gh`).

```
> почему в v2.3 поменяли логику ретраев? посмотри git log и blame
> реши конфликты мерджа, сохранив нашу логику кеширования
> создай PR с описанием изменений и чек-листом тестирования
```

Установите `gh` CLI — Claude будет работать с issues и PR.

## 9. Курс-коррекция

- Прерывайте рано (`Esc`), не ждите конца.
- Если после 2 исправлений всё ещё не то — `/clear` и новый, лучший промпт.
- «Сначала объясни, что собираешься сделать» — дешёвая страховка.

## 10. Шаблон рабочего дня

```
Утро:   claude -c  → «на чём мы остановились? прочитай PLAN.md»
Задача: /clear → explore → plan mode → код с тестами → /review → коммит
Вечер:  «обнови PLAN.md: что сделано, что дальше»
```

## Практика

1. Решите одну задачу строго по циклу Explore → Plan → Code → Commit.
2. Сделайте одну функцию через TDD.
3. Посмотрите `/context` в середине длинной задачи, выполните `/compact` с фокусом.
