# Модуль 01. Основы работы и промптинг

## Главная идея

Claude Code — это сильный инженер, который **впервые видит ваш проект** и **не помнит прошлых разговоров** (кроме CLAUDE.md и авто-памяти). Качество результата = качество постановки задачи + контекст + способ проверки.

## Формула хорошего промпта

```
[Что сделать] + [Где] + [Ограничения] + [Как проверить]
```

❌ Плохо:
```
почини логин
```

✅ Хорошо:
```
Пользователи жалуются, что после истечения сессии логин падает с 500.
Посмотри src/auth/ — особенно refresh токена. Напиши падающий тест,
который воспроизводит проблему, потом исправь. Не меняй публичный API.
Проверь: npm test -- auth
```

## Приёмы

### 1. Указывайте файлы через `@`
```
> отрефактори @src/utils/date.ts по примеру @src/utils/money.ts
```

### 2. Давайте примеры и паттерны
«Сделай как в X» работает лучше длинных описаний стиля.

### 3. Вставляйте изображения
Перетащите скриншот в терминал (или `Ctrl+V`) — макеты, ошибки, графики.
```
> сверстай компонент по этому макету, потом сделай скриншот и сравни
```

### 4. Передавайте данные через pipe
```bash
cat error.log | claude -p "найди первопричину ошибки"
git diff main | claude -p "сделай ревью изменений"
```

### 5. Просите подумать
Для сложных задач: «продумай несколько вариантов и выбери лучший», «подумай внимательно (think hard)». Расширенное мышление также включается в `/config` или `Tab` в некоторых версиях.

### 6. Задавайте вопросы о коде
Онбординг в новый проект — одно из лучших применений:
```
> как работает логирование?
> почему здесь вызывается foo(), а не bar()? посмотри историю git
> какие edge cases не покрыты в @src/parser.ts?
```

### 7. Корректируйте рано
- `Esc` — остановить, если Claude пошёл не туда.
- `Esc Esc` — откатиться и переформулировать.
- «Стоп, сначала покажи план» — лучше, чем исправлять 20 файлов.

### 8. Одна сессия — одна задача
Переключились на другую задачу → `/clear`. Мусор в контексте ухудшает ответы и стоит денег.

## Анти-паттерны

| Анти-паттерн | Что делать |
|---|---|
| «Сделай всё хорошо» | Критерии готовности, команды проверки |
| 3 часа в одной сессии на 5 задач | `/clear` между задачами |
| Исправлять ошибку Claude 5-й раз подряд | `/clear` + лучший промпт с учётом уроков |
| «Исследуй весь проект» | Конкретизируйте или используйте subagent |
| Слепо принимать всё | Читайте диффы, особенно в auth/платежах/миграциях |

## Практика

1. Возьмите реальный баг. Сформулируйте задачу по формуле: что, где, ограничения, проверка.
2. Попросите Claude сначала **только** исследовать и описать причину — без правок.
3. Потом попросите тест + исправление.
