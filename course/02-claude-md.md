# Модуль 02. CLAUDE.md — память проекта

`CLAUDE.md` — файл, который Claude автоматически читает в начале каждой сессии. Это «инструкция для нового сотрудника»: команды, стиль, архитектура, запреты.

## Иерархия файлов памяти

| Уровень | Путь | Кому | В git? |
|---|---|---|---|
| Организация (managed) | `/etc/claude-code/CLAUDE.md` (Linux), `/Library/Application Support/ClaudeCode/CLAUDE.md` (macOS) | Всем в компании | — |
| Пользователь | `~/.claude/CLAUDE.md` | Вам во всех проектах | нет |
| Проект | `./CLAUDE.md` или `./.claude/CLAUDE.md` | Всей команде | **да** |
| Локальный | `./CLAUDE.local.md` | Вам в этом проекте | нет (в .gitignore) |
| Подпапки | `./packages/api/CLAUDE.md` | Подгружается, когда Claude работает в этой папке | да |

Все уровни объединяются; более специфичный дополняет более общий.

## Быстрый старт

```
/init        # Claude проанализирует проект и создаст CLAUDE.md
/memory      # открыть файлы памяти в редакторе
# всегда используй pnpm, не npm     ← строка с # сохраняется в память
```

## Импорты

Не раздувайте файл — ссылайтесь:

```markdown
См. @README.md для обзора и @package.json для команд.

# Подробные правила
- Git workflow: @docs/git-workflow.md
- Личные настройки: @~/.claude/my-preferences.md
```

## Модульные правила: `.claude/rules/`

Для больших проектов разбейте правила по темам и привяжите к путям:

```markdown
---
paths:
  - "src/api/**/*.ts"
---
# Правила API
- Все эндпоинты валидируют вход через zod
- Ошибки — только через ApiError
```

Такое правило подгружается, только когда Claude работает с подходящими файлами — экономия контекста.

## Что писать в CLAUDE.md

✅ Пишите:
- Команды: сборка, тесты (включая запуск **одного** теста), линт, типы.
- Стиль кода, который не ловит линтер.
- Архитектурные решения и «где что лежит».
- Git-правила: ветки, формат коммитов.
- Особенности окружения, грабли, «никогда не делай X».

❌ Не пишите:
- То, что Claude и так поймёт из кода.
- Длинные туториалы (вынесите в docs и импортируйте).
- Секреты и токены.
- Устаревшую информацию — она вреднее отсутствия.

## Правила хорошего CLAUDE.md

1. **Коротко.** Цель — до ~200 строк. Каждая строка тратит контекст в каждой сессии.
2. **Конкретно.** «Используй 2 пробела» лучше, чем «форматируй аккуратно».
3. **Акценты.** Для критичных правил: `ВАЖНО:` / `НИКОГДА`. Но не злоупотребляйте.
4. **Итерируйте.** Claude ошибся одинаково дважды → добавьте правило. Правило не работает → переформулируйте или удалите.
5. **Проверяйте.** `/context` покажет, какие файлы памяти загружены и сколько весят.
6. **Ревьюйте как код.** CLAUDE.md в git, изменения — через PR.

## Шаблон

Готовый пример: [`starter-kit/CLAUDE.md`](../starter-kit/CLAUDE.md)

```markdown
# Проект: Acme API

## Команды
- `pnpm dev` — dev-сервер
- `pnpm test` — все тесты; `pnpm test path/to/file` — один файл
- `pnpm lint && pnpm typecheck` — обязательно перед коммитом

## Стиль
- TypeScript strict, без `any`
- Именованные экспорты, без default export

## Архитектура
- src/routes → src/services → src/repositories (слои не перепрыгивать)

## Workflow
- Сначала тест, потом код
- Коммиты: Conventional Commits

## Никогда
- Не редактируй миграции, которые уже в main
- Не коммить .env
```

## AGENTS.md

Если в проекте уже есть `AGENTS.md` (общий стандарт для AI-агентов), Claude Code может его читать. Поведение настраивается в `/config`. Простой способ поддерживать оба — в `CLAUDE.md` написать `@AGENTS.md`.

## Практика

1. Выполните `/init`, прочитайте результат и **сократите на треть**.
2. Добавьте команду запуска одного теста.
3. Через `#` добавьте одно правило и найдите, куда оно записалось.
4. Создайте `CLAUDE.local.md` с личными предпочтениями.
