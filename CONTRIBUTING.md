# Как помочь курсу

Спасибо, что хотите сделать курс лучше! Claude Code быстро меняется, и свежие исправления особенно ценны.

## Что можно сделать
- 🐛 **Исправить неточность** — команда устарела, поле переименовано, опечатка.
- 🧪 **Добавить лабу или рецепт** — `labs/`, `recipes/prompts.md`.
- 🧩 **Добавить шаблон** — skill, агент, hook, правило в `starter-kit/`.
- 🌍 **Улучшить объяснение** — если что-то было непонятно вам, будет непонятно и другим.

## Правила
1. **Точность важнее полноты.** Сверяйтесь с https://code.claude.com/docs. Не уверены — отметьте это в PR.
2. **Практичность.** Каждый раздел отвечает на вопрос «как это использовать в работе».
3. **Кратко.** Таблицы и примеры лучше длинных абзацев.
4. **Шаблоны должны работать.** Skills — с `name` и `description`, имя совпадает с папкой. Скрипты — проходят `bash -n` и `shellcheck`.
5. **Без секретов** в примерах — только `${VAR}`.

## Перед PR

```bash
pip install pyyaml
python3 scripts/validate.py      # JSON, frontmatter, bash, ссылки
shellcheck $(git ls-files '*.sh') # если установлен
```

Эти же проверки запускает CI ([validate.yml](.github/workflows/validate.yml)).

## Стиль текста
- Русский язык, обращение на «вы».
- Термины как в документации: skill, subagent, hook, MCP, plan mode.
- Код и команды — в блоках кода; пути и имена файлов — в `моноширинном`.
- Каждый модуль заканчивается разделом **Практика** и ссылкой на следующий модуль.

## Работа с Claude Code над этим репозиторием
В репозитории есть [CLAUDE.md](CLAUDE.md) — Claude Code сразу знает правила проекта. Попробуйте:
```
> /code-review
> проверь course/05-skills.md на соответствие актуальной документации
```
