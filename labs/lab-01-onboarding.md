# Лаба 1. Онбординг в проект и CLAUDE.md

**Цель:** за 30 минут понять незнакомый проект и оставить после себя качественный CLAUDE.md.

## Шаги

1. Откройте проект и задайте обзорные вопросы:
   ```
   > Опиши архитектуру: стек, точки входа, слои, где бизнес-логика.
   > Как запустить проект, все тесты и ОДИН тест? Проверь, что команды реально работают.
   > Какие 3 места в коде самые рискованные для изменений и почему?
   ```
2. Выполните `/init`. Прочитайте получившийся `CLAUDE.md`.
3. Попросите Claude сократить его:
   ```
   > Сократи CLAUDE.md до самого важного: команды, архитектура в 5 строк,
     стиль, который не ловит линтер, запреты. Убери всё, что очевидно из кода.
   ```
4. Добавьте через `#` одно правило, например: `# тесты запускай через pnpm test <файл>, не весь набор`.
5. Создайте `CLAUDE.local.md` с личными предпочтениями (язык ответов, локальные URL).
6. Выполните `/clear`, затем `/context` — посмотрите, сколько весит память.

## ✅ Готово, если
- [ ] CLAUDE.md < 100 строк и содержит команду запуска одного теста
- [ ] Команды из CLAUDE.md проверены запуском
- [ ] `CLAUDE.local.md` в `.gitignore`
- [ ] В новой сессии Claude отвечает «как запустить тесты?» без поиска по файлам

## 💡 Подсказка
Хороший тест качества CLAUDE.md: попросите новую сессию сделать мелкую задачу и посмотрите, сколько файлов она читает «на разведку». Меньше — лучше.
