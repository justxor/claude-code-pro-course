# Code review

## Шаги
1. Определи базу: `git diff main...HEAD --stat` (если main нет — `master`). Если изменений в ветке нет — используй `git diff` и `git diff --staged`.
2. Прочитай полный дифф и, где нужно, окружающий код изменённых файлов.
3. Проверь каждый файл по чек-листу:
   - **Корректность:** логика, граничные случаи (null, пусто, большие значения), обработка ошибок
   - **Безопасность:** инъекции, секреты в коде, проверка прав, валидация ввода
   - **Тесты:** покрыто ли новое поведение; не ослаблены ли существующие тесты
   - **Производительность:** N+1, лишние циклы, утечки
   - **Читаемость:** имена, дублирование, соответствие стилю из CLAUDE.md
4. Не придумывай проблем ради количества. Нет замечаний — так и скажи.

## Формат отчёта
```
## Итог: <одно предложение>

### 🔴 Критично
- `файл:строка` — проблема → предложение

### 🟡 Стоит исправить
- ...

### 🟢 Мелочи
- ...
```
